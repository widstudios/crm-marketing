# Regole — Internazionalizzazione

> Chiavi in inglese, testi tradotti, formati localizzati. Ogni progetto nasce multilingua anche
> quando ha una sola lingua attiva.

## Descrizione

Predisporre la traduzione costa quasi nulla durante lo sviluppo; aggiungerla dopo richiede di
toccare ogni vista, ogni notifica e ogni messaggio di errore.

La seconda lingua arriva sempre: un cliente con una sede estera, una gara che la richiede, un
operatore che non parla italiano.

---

## Regole

**R1.** Ogni stringa visibile all'utente passa da `__()`.
*Verifica:* ricerca in CI su testo letterale nelle viste. *Livello: vincolante.*

**R2.** Le chiavi sono in **inglese**, gerarchiche, in `snake_case`.
*Motivo:* una chiave italiana diventa assurda quando si aggiunge l'inglese.
*Verifica:* revisione.

**R3.** La lingua di ripiego è l'italiano.
*Verifica:* configurazione.

**R4.** Le lingue supportate di serie sono `it` e `en`.
*Verifica:* presenza dei file di lingua.

**R5.** Ogni modulo ha i propri file di traduzione, con spazio dei nomi.

```php
__('inventory::batch.expiry_date')
```

*Verifica:* struttura del modulo.

**R6.** Nessuna stringa duplicata tra file: i testi comuni stanno in `common.php`.
*Verifica:* revisione.

**R7.** I messaggi di eccezione restano in inglese; la traduzione avviene nella presentazione.
*Motivo:* i log devono essere leggibili indipendentemente dalla lingua dell'utente.
*Verifica:* revisione.

**R8.** Le chiavi non usate si rimuovono; le chiavi mancanti fanno fallire la verifica in CI.
*Verifica:* script di confronto tra chiavi usate e definite.

## Struttura delle chiavi

```php
// resources/lang/it/inventory.php  (o modules/inventory/resources/lang/it/)
return [
    'batch' => [
        'singular' => 'Lotto',
        'plural' => 'Lotti',
        'number' => 'Numero lotto',
        'expiry_date' => 'Data di scadenza',
    ],
    'status' => [
        'available' => 'Disponibile',
        'reserved' => 'Impegnato',
        'expired' => 'Scaduto',
    ],
    'action' => [
        'pick' => 'Prelevare',
        'quarantine' => 'Mettere in quarantena',
    ],
    'notification' => [
        'expiring' => [
            'subject' => 'Lotti in scadenza',
            'line' => 'Il lotto :number scade tra :days giorni.',
        ],
    ],
    'error' => [
        'insufficient_stock' => 'Disponibilità insufficiente: :available unità.',
    ],
];
```

**R9.** L'ambito della chiave riflette il **dominio**, non la posizione nell'interfaccia.
*Motivo:* se la pagina cambia, la chiave resta valida.
*Verifica:* revisione.

**R10.** Ogni entità dichiara `singular` e `plural`: servono a etichette, titoli e messaggi.
*Verifica:* revisione.

## Formati

**R11.** Date, numeri e valute si formattano per **locale**, mai a mano.

```php
// ✗ Formato fisso
$date->format('d/m/Y');

// ✓ Localizzato
$date->isoFormat('L');
Number::currency($amount, 'EUR', app()->getLocale());
```

*Verifica:* revisione.

**R12.** Nel database tutto in UTC; la conversione avviene in presentazione, sul fuso del tenant.
*Verifica:* configurazione, revisione.

**R13.** I separatori decimali e delle migliaia seguono il locale.
*Verifica:* revisione.

**R14.** Le unità di misura sono tradotte, i simboli restano invariati.
*Verifica:* revisione.

## Plurali e parametri

**R15.** I plurali usano `trans_choice()`, non condizioni nel codice.

```php
// resources/lang/it/inventory.php
'batches_count' => '{0} Nessun lotto|{1} Un lotto|[2,*] :count lotti',
```

```php
trans_choice('inventory.batches_count', $count, ['count' => $count]);
```

*Verifica:* revisione.

**R16.** I parametri hanno nomi descrittivi, non posizionali.
*Verifica:* revisione.

**R17.** Nessuna concatenazione di frasi tradotte.

```php
// ✗ L'ordine delle parole cambia tra le lingue
__('common.the_batch') . ' ' . $number . ' ' . __('common.is_expired');

// ✓ Frase intera con parametri
__('inventory.batch_expired', ['number' => $number]);
```

*Motivo:* la struttura della frase varia tra le lingue.
*Verifica:* revisione. *Livello: vincolante.*

## Contenuti di dominio

**R18.** I termini del cliente si mappano nel glossario di progetto e si traducono
nell'interfaccia, senza toccare il codice.

| Termine del cliente | Concetto | Codice | Traduzione |
|---|---|---|---|
| commessa | progetto | `Project` | `projects.singular => 'Commessa'` |
| bolla | documento di trasporto | `DeliveryNote` | `delivery_notes.singular => 'Bolla'` |

*Motivo:* se il secondo cliente usa un termine diverso, cambia un file di lingua.
*Verifica:* revisione.

**R19.** I contenuti inseriti dagli utenti (nomi di articoli, note) non si traducono: sono dati.
*Verifica:* revisione.

**R20.** I contenuti CMS sono multilingua a livello di dato, con `locale` sull'entità.
*Verifica:* schema.

## Esempi

### Esempio 1 — enum tradotto

```php
enum BatchStatus: string
{
    case Available = 'available';
    case Expired = 'expired';

    public function label(): string
    {
        return __("inventory::status.{$this->value}");
    }
}
```

Il valore nel database resta stabile; l'etichetta segue la lingua dell'utente.

### Esempio 2 — violazioni

```blade
{{-- ✗ R1: testo nella vista --}}
<h1>Elenco lotti</h1>

{{-- ✗ R11: formato fisso --}}
<td>{{ $batch->expiry_date->format('d/m/Y') }}</td>

{{-- ✗ R17: concatenazione --}}
<p>{{ __('common.total') }}: {{ $count }} {{ __('common.items') }}</p>
```

## Best practice

- Scrivere la chiave di traduzione mentre si scrive la vista, non dopo.
- Usare `singular` e `plural` per generare etichette coerenti.
- Verificare le chiavi mancanti in CI: è l'unico modo per non accumularle.
- Provare l'interfaccia in inglese ogni tanto: rivela le stringhe dimenticate.

## Errori comuni

| Errore | Conseguenza | Rimedio |
|---|---|---|
| Testo scritto nelle viste | Seconda lingua impossibile senza riscrittura | `__()` |
| Chiavi in italiano | Assurde con la seconda lingua | Chiavi in inglese |
| Chiavi per posizione nell'interfaccia | Non più valide quando la pagina cambia | Chiavi per dominio |
| Formato di data fisso | Errato per altri locale | Formattazione localizzata |
| Concatenazione di frasi | Ordine delle parole errato | Frase intera con parametri |
| Plurali con `if` | Regole di plurale diverse tra lingue | `trans_choice()` |
| Termine del cliente nel codice | Riscrittura al cliente successivo | Mappatura nel glossario |
| Chiavi mancanti non rilevate | Testi grezzi in produzione | Verifica in CI |

## Checklist

- [ ] Ogni stringa visibile passa da `__()`.
- [ ] Chiavi in inglese, gerarchiche, per dominio.
- [ ] File di lingua `it` e `en` presenti e allineati.
- [ ] Ogni entità dichiara `singular` e `plural`.
- [ ] Date, numeri e valute formattati per locale.
- [ ] UTC nel database, conversione in presentazione.
- [ ] Plurali con `trans_choice()`.
- [ ] Nessuna concatenazione di frasi tradotte.
- [ ] Termini del cliente mappati nel glossario, non nel codice.
- [ ] Verifica delle chiavi mancanti in CI.
